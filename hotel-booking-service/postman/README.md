# Postman: импорт и демонстрация

В папке два файла:

- `HotelBooking.postman_collection.json` — **23 запроса**;
- `HotelBooking.postman_environment.json` — окружение с адресом и переменными.

Коллекция повторяет [`../POSTMAN_REQUESTS.md`](../POSTMAN_REQUESTS.md):
4 подготовительных запроса, 15 обязательных методов и 4 ошибки.

## 1. Импорт

1. Открой Postman.
2. `Import` → выбери оба JSON-файла из этой папки.
3. В правом верхнем углу выбери окружение **Hotel Booking Local**.
4. Открой коллекцию **Hotel Booking — 23 запроса**.

## 2. Подготовка базы

Перед защитой лучше сделать чистый старт:

```bash
cd /Users/daria/Documents/Study/oop/hotel-booking-service
./reset-db.sh
./mvnw spring-boot:run
```

После запуска `DataInitializer` создаст:

- 5 отелей;
- 21 номер;
- 10 клиентов;
- 25 бронирований во всех статусах.

## 3. Порядок выполнения

Коллекция состоит из трёх папок:

| Папка | Что делает |
|---|---|
| `01. Подготовка` | получает/создаёт типы номеров и клиентов |
| `02. Обязательные методы` | 15 запросов из таблицы задания |
| `03. Ошибки` | 400, 404 и 409 |

Выполняй папки сверху вниз.

## 4. Автоматические переменные

В коллекции есть небольшие скрипты. Это **не JUnit-тесты**, они только
сохраняют id из ответов:

| Запрос | Что сохраняет |
|---|---|
| `GET типы номеров` | `roomTypeId` |
| `GET клиенты` | `clientId` |
| `POST создать отель` | `newHotelId` |
| `POST создать номер` | `newRoomId` |
| `POST создать бронь` | `newBookingId` |

Поэтому после `POST создать отель` запросы `PUT` и `DELETE` уже сами
подставляют нужный id. После `POST создать бронь` запрос `confirm`
тоже подставляет id автоматически.

## 5. Что показывать

1. `01. Подготовка` — «получаю существующие id типов номеров и клиентов».
2. `02. Обязательные методы`:
   - `GET отели по городу` — данные из БД;
   - `POST создать отель` → `PUT` → `DELETE` — полный CRUD;
   - `GET номера отеля с фильтром` — фильтрация;
   - `POST создать номер` — создание;
   - `PUT изменить номер` — изменение;
   - `GET свободные номера` — поиск на даты;
   - `POST создать бронь` → `GET` → `confirm` — расчёт и подтверждение;
   - `POST отменить бронь` — отмена;
   - `GET статистика` — сумма и группировка.
3. `03. Ошибки` — пересечение `409`, вместимость `400`,
   несуществующий отель `404`, неверные даты `400`.

## 6. Если запускаешь повторно

Папка `01` создаёт тип номера «Апартаменты» и клиента
`maria.demo@mail.ru`. При повторном запуске они уже существуют → `409`.
Это нормально.

Для чистой демонстрации:

```bash
./reset-db.sh
```

и перезапусти приложение.
